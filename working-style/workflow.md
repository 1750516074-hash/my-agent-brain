# working-style/workflow.md — 做事流程

> **status: draft。** 流程骨架已就位，「待填」处需要本人确认后才算数。
> 骨架本身是通用结构，不是本人的习惯——Agent 用它保证不漏步骤，但不要声称「这是你的偏好」。

## 一个任务的五个阶段

| 阶段 | 要做的事 | 待填 |
|------|----------|------|
| 1 接 | 复述目标 + 边界 + 验收标准，一句话 | 需要复述吗，还是直接干 |
| 2 判 | 有没有不确定的地方？风险等级？要不要先问 | 什么情况下必须先确认 |
| 3 做 | 按 [`principles.md`](principles.md) 的取舍推进 | 中途要不要同步进度 |
| 4 校 | 对照 [`delivery-checklist.md`](delivery-checklist.md) 自检 | 谁验、验到什么程度 |
| 5 交 | 结论 + 产物路径 + 已知风险 + 下一步 | 要不要给下一步建议 |

## 阶段 1 的复述模板

```
目标：
边界：（不做什么）
验收：怎样算完成
```

## 阶段 2 的风险分级

| 等级 | 例子 | 动作 |
|------|------|------|
| 低 | 读文件、查资料、本地草稿 | 直接做 |
| 中 | 改代码、写文档、跑脚本 | 做完说清楚改了什么 |
| 高 | 删数据、花钱、对外发布、发邮件 | **先问，再动** |

## 返工时怎么记

返工不是失败，是信息。每次返工在 `memory/log/YYYY-MM-DD.md` 记一条：

```
- 原方案：
- 改成了：
- 原因：（写真正的理由，不是「优化」）
- 是否重复出现：
```

同一个原因出现三次，升级成 `working-style/principles.md` 里的原则。
