# working-style/delivery-checklist.md — 交付前自检

> **status: draft。** 这份清单是通用工程常识，不是本人已确认的标准。
> 用它可以减少低级失误，但不要把它当成「这就是他要的质量」。

## 每次交付都过一遍

**做完了吗**

- [ ] 声称完成的部分，我真的运行 / 打开 / 查看过吗？
- [ ] 有没有「应该没问题」这种没验证就下的结论？
- [ ] 交付物在哪，路径写清楚了吗？

**说清楚了吗**

- [ ] 第一句是不是结论？读的人能不能只看第一句就知道结果？
- [ ] 我做的假设有没有明写出来？
- [ ] 没做到的部分、放弃的部分，说了吗？还是悄悄略过了？

**对不对**

- [ ] 有没有违反 [`do-not/never.md`](../do-not/never.md) 的硬约束？
- [ ] 有没有和已有记忆冲突？冲突时我是提了 PR，还是自己改了行为？
- [ ] 数字、文件名、命令、链接，逐字核对过吗？

**收尾**

- [ ] 有没有需要本人决策但被我替你决定了的地方？
- [ ] 有没有留下半成品或临时文件？
