# meta/open-questions.md — 待回答的问题

这份库目前最缺的不是结构，是**你的事实**。
下面每个问题都对应一个空槽。答一次，所有读这个库的 Agent 都能受益；不答，它们只能每次重新猜。

**怎么答**：不用按顺序，捡想答的答，直接回给我就行，我负责填进对应文件、改 `status` 和 `confidence`。
答一半也算数——填进去的每一格都会立刻生效。

---

## A. 我是谁 → `identity/who-i-am.md`

1. 我该怎么称呼你？
2. 你的职业 / 角色是什么？一句话就够。
3. 你现在手上主要在做哪两三件事？
4. 常用什么操作系统、什么工具链、什么语言？
5. 什么时段效率最高？能接受多长的反馈周期？

## B. 怎么说话 → `identity/how-to-talk-to-me.md`

6. 交付时希望第一句是什么？（结论 / 背景 / 反问）
7. 喜欢表格和清单，还是连贯的段落？
8. 「为什么这么做」要讲多深？一句话 / 一段 / 完整推演？
9. 有哪些词或句式你看到就烦？（例：综上所述、赋能、让我们一起…）

## C. 怎么判断 → `working-style/principles.md`

每题选一边，或者告诉我「看情况」以及看什么情况：

10. 先交付 80% 能用的，还是等 100% 再给？
11. 自己拍板，还是先问一遍？
12. 同一个问题，倾向抽成通用方案，还是就地解决？
13. 沿用项目旧约定，还是引入更好的做法？
14. 一个方向做透，还是先铺开验证？

## D. 硬约束 → `do-not/never.md`

15. 有没有「不管什么情况都别做」的事？写三条最有代表性的。
16. 有没有「必须做但 Agent 经常忘」的事？

## E. 验收标准 → `working-style/delivery-checklist.md`

17. 什么程度算「可以交付」？
18. 哪些错误你零容忍？哪些可以事后再修？
19. 交付时希望附上什么？（验证过程 / 截图 / 下一步建议）
